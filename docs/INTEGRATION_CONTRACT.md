# Little Monkey Café Dining — Google Integration Contract

## 1. Endpoint Overview

- **Protocol:** HTTPS
- **Method:** `POST`
- **Content-Type:** `application/json`
- **Authentication:** Mandatory HMAC-SHA256 request signing using server-only shared secret (`SHARED_API_KEY` in Apps Script, `GOOGLE_SHEETS_API_KEY` on Dining server).
- **Execution Model:** Hosted Google Apps Script Web App (`Execute as: Me`, `Who has access: Anyone`), called exclusively by the Dining backend relay.

---

## 2. Request Contract

### Headers
```http
Content-Type: application/json
Accept: application/json
```

### JSON Request Schema (Dining Server to Google Apps Script)
```json
{
  "type": "object",
  "properties": {
    "timestamp": {
      "type": "string",
      "format": "date-time",
      "description": "ISO 8601 UTC timestamp of request generation. Checked against a 5-minute tolerance window."
    },
    "nonce": {
      "type": "string",
      "minLength": 16,
      "maxLength": 64,
      "description": "Cryptographic random hex string to prevent replay attacks."
    },
    "name": {
      "type": "string",
      "minLength": 1,
      "maxLength": 60,
      "description": "Customer full name."
    },
    "mobile": {
      "type": "string",
      "pattern": "^[6-9]\\d{9}$",
      "description": "10-digit Indian mobile number."
    },
    "confirmedExistingName": {
      "type": "boolean",
      "description": "Flag indicating diner explicitly confirmed using existing record name despite discrepancy."
    },
    "signature": {
      "type": "string",
      "pattern": "^[a-f0-9]{64}$",
      "description": "Hex-encoded HMAC-SHA256 signature of canonical payload."
    }
  },
  "required": ["timestamp", "nonce", "name", "mobile", "signature"],
  "additionalProperties": false
}
```

### Canonical String Specification
Before computing the HMAC-SHA256 signature, the parameters are serialized into a strict canonical string:
```text
canonicalString = `${timestamp}:${nonce}:${name.trim()}:${mobile.trim()}:${confirmedExistingName ? 'true' : 'false'}`
```

### Signature Computation
- **Node.js (Dining Server):**
  ```typescript
  const signature = crypto.createHmac('sha256', secret).update(canonicalString).digest('hex').toLowerCase();
  ```
- **Google Apps Script:**
  ```javascript
  var signatureBytes = Utilities.computeHmacSha256Signature(canonicalString, sharedSecret);
  var expectedSignature = toHex(signatureBytes);
  // Constant-time comparison
  constantTimeCompare(expectedSignature, providedSignature);
  ```

### Field Normalization Rules

| Field | Source Input | Normalization Procedure |
| :--- | :--- | :--- |
| **`timestamp`** | Generated by server | ISO 8601 format (`new Date().toISOString()`). Must be within ±5 minutes of server time. |
| **`nonce`** | Generated by server | 16-byte random hex string (`crypto.randomBytes(16).toString('hex')`). Replay rejection via cache. |
| **`name`** | User string | Trim leading/trailing whitespace. Length must be 1 to 60 characters. Neutralized against formula injection (`'`). |
| **`mobile`** | User string | Strip all non-digit characters (`\D`). If 12 digits starting with `91`, strip `91`. If 11 digits starting with `0`, strip `0`. Validate exact regex `^[6-9]\d{9}$`. |
| **`signature`** | Generated by server | 64-character lowercase hex digest of HMAC-SHA256 over canonical string. |

## 3. Response Contracts

> [!NOTE]
> Google Apps Script `ContentService` always returns HTTP 200 at the transport layer. The Dining Server inspects `gasData.success`, `gasData.status`, and `gasData.error` to map responses to proper REST status codes for the dining client application.

### A. New Customer Created (HTTP 201 Created)
```json
{
  "success": true,
  "status": "NEW_CUSTOMER",
  "customer": {
    "customerId": "CUST-8F3A2E10",
    "name": "Aarav Sharma",
    "mobile": "9876543210"
  },
  "message": "Customer record registered successfully."
}
```

### B. Existing Customer Verified (HTTP 200 OK)
Returned when a row already exists with the exact same mobile number and matching name.
```json
{
  "success": true,
  "status": "EXISTING_CUSTOMER",
  "customer": {
    "customerId": "CUST-8F3A2E10",
    "name": "Aarav Sharma",
    "mobile": "9876543210"
  },
  "message": "Welcome back! Customer record verified."
}
```

### C. Existing Customer with Name Discrepancy (HTTP 200 OK)
Returned when a row exists with the mobile number, but the submitted name differs from the stored name. The stored name is strictly preserved to prevent silent overwrite.
```json
{
  "success": true,
  "status": "EXISTING_CUSTOMER_NAME_MISMATCH",
  "customer": {
    "customerId": "CUST-8F3A2E10",
    "name": "Aarav Sharma",
    "submittedName": "Aarav S.",
    "mobile": "9876543210"
  },
  "message": "Existing customer record found with a different name. Existing name preserved."
}
```

## 4. Error Responses

### A. Missing or Empty Payload (HTTP 400 Bad Request)
```json
{
  "success": false,
  "error": "EMPTY_REQUEST",
  "message": "No request payload received."
}
```

### B. Invalid Name (HTTP 422 Unprocessable Entity)
```json
{
  "success": false,
  "error": "INVALID_NAME",
  "message": "Customer name must be between 1 and 60 characters."
}
```

### C. Invalid Mobile Number (HTTP 422 Unprocessable Entity)
```json
{
  "success": false,
  "error": "INVALID_MOBILE",
  "message": "Mobile number must be a valid 10-digit Indian mobile number starting with 6, 7, 8, or 9."
}
```

### D. Authentication Failure (HTTP 401 Unauthorized)
Returned when the HMAC-SHA256 signature does not match or is missing.
```json
{
  "success": false,
  "error": "INVALID_SIGNATURE",
  "message": "Cryptographic request signature verification failed."
}
```

### E. Replay / Stale Request (HTTP 403 Forbidden)
Returned when the timestamp is outside the 5-minute window or the nonce has already been used.
```json
{
  "success": false,
  "error": "REQUEST_EXPIRED",
  "message": "Request timestamp is outside the allowed 5-minute tolerance window."
}
```
Or:
```json
{
  "success": false,
  "error": "DUPLICATE_NONCE",
  "message": "Request replay detected. This nonce has already been used."
}
```

### F. Concurrency / Lock Contention (HTTP 503 Service Unavailable)
Returned if the atomic script lock could not be acquired within 10 seconds.
```json
{
  "success": false,
  "error": "LOCK_TIMEOUT",
  "message": "Server is processing concurrent customer registrations. Please retry in a moment."
}
```

### G. Server Configuration or Internal Error (HTTP 500 Internal Server Error)
```json
{
  "success": false,
  "error": "SERVER_MISCONFIGURED",
  "message": "Server authentication is not configured."
}
```
Or:
```json
{
  "success": false,
  "error": "INVALID_HEADERS",
  "message": "Worksheet schema mismatch. Expected headers: customer_id, name, mobile_number, created_at, updated_at."
}
```
Or:
```json
{
  "success": false,
  "error": "SERVER_ERROR",
  "message": "An unexpected error occurred while processing the customer record."
}
```
